1. Current structure (from code)

LayerWhereWhat it does today
Primitive width refs _primitive-size.scss $cml-ref-size-breakpoint-0/768/1024/1680 → map to $cml-base-size-*
Semantic breakpoints _semantic-breakpoint.scss $cml-sys-breakpoint-standard-*, landing-*, admin-*
Grid maps _semantic-grid.scss Each grid map holds a breakpoint: key (width only)
Consumer API _media.scss @mixin respond($device) → @media (min-width: …) only
JS helper utils/breakpoint.ts matchMedia('(min-width: 1024px)') — width only
Important naming collision already in repo Device frame tokens already use Portrait/Landscape in the name (e.g. $cml-ref-size-device-width-Ipad-Portrait). Those are frame sizes, not CSS orientation media. Do not bake orientation into $cml-ref-size-breakpoint-* names — easy to confuse with device frames.

2. Constraint of today’s responsive tokens

  • Breakpoints are pixel widths, not layout axes.
  • Orientation is a media feature (portrait / landscape), not a size number — so it does not belong as a new “breakpoint size” value.
  • ~250+ call sites use @include respond(...); renaming tokens forces wide churn.
  • TS desktop watchers also assume width-only.

3. Options we can actually do

Recommended A. Keep width tokens · extend the mixin (query layer)

Orientation becomes an optional second axis on the mixin, not a new size token. Old tokens and respond($device) stay valid. 

// _media.scss — additive, non-breaking
@mixin respond($device, $orientation: null) {
  $bp: map.get($breakpoints, $device);

  @if $bp == null and $orientation == null {
    @content;
  } @else if $bp == null {
    @media (orientation: #{$orientation}) { @content; }
  } @else if $orientation == null {
    @media (min-width: $bp) { @content; }
  } @else {
    @media (min-width: $bp) and (orientation: #{$orientation}) {
      @content;
    }
  }
}
ProsCons
Zero rename · matches how CSS works · small diff · optional opt-in Orientation isn’t a “token name” in the sheet (it’s a query arg)

Optional add-on B. Tiny orientation keyword constants (not size breakpoints)

If designers/devs want named constants (not new widths): 

// e.g. _semantic-orientation.scss (new)
$cml-sys-orientation-portrait: portrait;
$cml-sys-orientation-landscape: landscape;

Use with the mixin: @include respond(tablet, $cml-sys-orientation-landscape). Still no change to $cml-ref-size-breakpoint-*.

Avoid C. Rename / fork width tokens per orientation 

// ❌ Do not do this as the primary API
$cml-ref-size-breakpoint-768-landscape: ...;
$cml-ref-size-breakpoint-768-portrait: ...;

Ambiguous vs device-frame tokens, forces consumer migration or a large alias matrix, and orientation is not a width value anyway.

4. Naming convention (fits CML today)

KindPatternExample
Width (unchanged) $cml-ref-size-breakpoint-{px} $cml-ref-size-breakpoint-768
Semantic width (unchanged) $cml-sys-breakpoint-{context}-{step} $cml-sys-breakpoint-standard-md
Orientation keywords (new, optional) $cml-sys-orientation-{portrait|landscape} $cml-sys-orientation-landscape
Query API respond($device, $orientation?) respond(desktop, landscape)
Device frames (existing — leave alone) $cml-ref-size-device-*-Ipad-Portrait Frame mock sizes, not media orientation

5. Token structure recommendation

base size
  └─ ref size breakpoint (width only)     ← keep public names
       └─ sys breakpoint / grid maps      ← keep
            └─ respond($device, $orientation?)   ← NEW axis here
                 └─ CSS: (min-width) and optional (orientation)

Default: omit orientation → today’s behavior.
Specific: pass portrait / landscape when the layout needs it.

8. Developer usage examples

// Today — still valid (no orientation)
@include respond(tablet) {
  .card { display: grid; grid-template-columns: 1fr 1fr; }
}

// Orientation only (any width)
@include respond(mobile, portrait) {
  .hero { flex-direction: column; }
}

// Breakpoint + orientation
@include respond(tablet, landscape) {
  .nav { display: flex; flex-direction: row; }
}

@include respond(desktop, portrait) {
  .sidebar { display: none; }
}
// Compiled CSS shape
@media (min-width: 768px) and (orientation: landscape) { ... }

9. Breakpoint × orientation — does it work together?

Yes. CSS media queries combine with and. The mixin above emits exactly that. Width tokens stay the source of min-width; orientation is a separate condition.
