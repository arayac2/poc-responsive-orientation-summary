Real solution — Device type × Breakpoints in CML

Plain-English for eng: keep the same width breakpoints we already ship. Add one extra question — “is this a tablet or a desktop?” — so a wide tablet does not accidentally get Desktop UI.

Same BPs0 / 768 / 1024 / 1680
Approach CHost tag first → pointer fallback
Not Navigator UADon’t sniff userAgent for layout

1. Problem in human words

Today CML mostly asks: “How many pixels wide is the window?” That works… until a tablet turns sideways.

Example: iPad landscape is often 1024px wide. Our Desktop breakpoint is also 1024. So width alone says “Desktop,” but product/design still want Tablet layout.

The opposite gray zone: a desktop that is portrait / narrower can feel “tablet-sized,” but if we know it’s a desktop, we still want Desktop UI once width hits 1024.

In one sentence Width tells us the band. Device type breaks the tie when tablet and desktop share the same width.

2. What we decided (Approach C)

Recommended Resolve device class in this order — then combine with existing breakpoints.

StepWhat eng doesHuman meaning
1 Read data-cml-device on <html> (tablet / desktop / mobile) Trust the host app if it already knows the platform
2 If missing → matchMedia('(hover: none) and (pointer: coarse)') vs fine+hover Guess touch-first vs mouse-first from the browser
3 If still unclear → width only Same behavior as today
Why not Navigator / userAgent? UA strings lie (iPad can look like Mac), change for privacy, and don’t match our CSS. Pointer + host tag stay aligned with what stylesheets can express.

3. Design rules eng must implement

If…Then use…
Device = tablet, width ≥ 768 (even if ≥ 1024 landscape)Tablet design — do not promote to Desktop
Device = desktop, width ≥ 1024 (including portrait)Desktop design
Device = desktop, width ≥ 1680Desktop large
No host tag + coarse pointerTreat like tablet for the gray zone
No host tag + fine pointerTreat like desktop for the gray zone
Product recommendation (open confirm) On tablet devices, suppress Desktop and Desktop-large tiers — stay on Tablet UI even at very large widths. Keeps the rule simple for design + eng.

SCSS — extend respond() in _media.scss

First paint / layout jump If the tag is set after components mount, UI can flip once (looks like shrink/expand). Set it in the document shell or very early boot. Init itself is sync — no async Navigator dance.

7. Checklist before coding in chameleon-design

  • Do not change breakpoint pixel values
  • Extend breakpoint.ts + _media.scss first (single source)
  • Keep component call sites (watchDesktopBreakpoint / respond(…)) stable if possible
  • Document host contract: set data-cml-device early
  • Smoke-test iPad landscape, desktop portrait, Storybook without host tag
  • Confirm with design: tablet suppresses desktop-large or not
Bottom line for eng Same breakpoints. Add device class (host tag → pointer/hover → width). Tablet landscape stays Tablet. Desktop portrait stays Desktop at ≥1024. No UA sniffing.
